### 1. Helm = Package Manager

**Helm is a package manager for Kubernetes.**

Iska matlab:

> Helm Kubernetes application ke deployment-related resources ko **Chart** ke form mein package karta hai aur unhe **install, upgrade, rollback aur uninstall** karne mein help karta hai.

Example:

```text
Spring Boot Application
        ↓
Helm Chart
        ↓
Deployment
Service
ConfigMap
Ingress
        ↓
Kubernetes
```

### 2. Terraform vs Helm

Tumhara concept:

> Terraform = infrastructure lifecycle
> Helm = Kubernetes application lifecycle

✅ **Ye interview ke liye good mental model hai.**

```text
Terraform
   ↓
Infrastructure lifecycle
   ↓
VPC
Subnet
IAM
EKS
EC2/Node Group
RDS
S3
```

Aur:

```text
Helm
   ↓
Kubernetes application lifecycle
   ↓
Deployment
Service
ConfigMap
Ingress
Secret
```

### Lekin ek correction

Tumne likha:

> “with Terraform only create EKS and rest inside deployment, pods etc all done by Helm”

**Ye mandatory rule nahi hai.**

Terraform **Kubernetes Deployment, Service, ConfigMap etc. bhi create kar sakta hai.**

Lekin practical setup mein often:

```text
Terraform → AWS/EKS infrastructure
Helm      → Applications inside Kubernetes
```

rakha jata hai because **separation of responsibility** aur application deployment ke liye Helm ka templating/versioning convenient hota hai.

# 3. Helm Chart structure

Typical Chart:

```text
my-app/
│
├── Chart.yaml
├── values.yaml
├── .helmignore
│
└── templates/
    ├── deployment.yaml
    ├── service.yaml
    ├── ingress.yaml
    └── _helpers.tpl
```

### `Chart.yaml`

Tumne likha:

> version of your application

⚠️ **Thoda correction:**

`Chart.yaml` **chart ki metadata** rakhta hai.

Example:

```yaml
apiVersion: v2
name: my-app
version: 1.0.0
appVersion: "2.5.0"
```

Important:

```text
version     → Helm Chart ka version
appVersion  → Application ka version
```

---

### `values.yaml`

Tumne likha:

> application variables

✅ Correct.

Yahan configurable values rakhte hain:

```yaml
replicaCount: 3

image:
  repository: myapp
  tag: "2.5"
```

Template mein:

```yaml
replicas: {{ .Values.replicaCount }}
```

Isse same Chart ko different environments mein reuse kar sakte ho.

```text
DEV  → replicas: 1
QA   → replicas: 2
PROD → replicas: 5
```

---

### `templates/`

Yahan **Kubernetes manifest templates** hote hain.

Example:

```text
templates/
├── deployment.yaml
├── service.yaml
├── ingress.yaml
└── configmap.yaml
```

Ye normal Kubernetes YAML jaise hi hain, lekin Helm variables use kar sakte hain:

```yaml
replicas: {{ .Values.replicaCount }}
```

---

### `.helmignore`

Tumne bola:

> like git .gitignore

✅ **Exactly.**

`.helmignore` batata hai ki Chart package banate waqt **kaunse files include nahi karne hain**.

Git mein:

```text
.gitignore
→ Git ko files track na karne ke liye
```

Helm mein:

```text
.helmignore
→ Helm package mein files include na karne ke liye
```

# 4. `_helpers.tpl` kya hai?

Tumhari understanding **almost perfect** hai.

> `_helpers.tpl` mein reusable Helm template/helper definitions rakhte hain.

Example:

```yaml
{{- define "myapp.fullname" -}}
{{ .Release.Name }}-{{ .Chart.Name }}
{{- end }}
```

Phir doosri template mein:

```yaml
name: {{ include "myapp.fullname" . }}
```

### Important

`_helpers.tpl` **directly Kubernetes resource create nahi karta.**

Ye mainly **reusable template snippets/functions** define karta hai.

```text
_helpers.tpl
      ↓
Reusable helper
      ↓
deployment.yaml / service.yaml
      ↓
Actual Kubernetes manifest
```

Aur `_` se start hone wali template files ko Helm normal manifest output ke roop mein render nahi karta.

# 5. Important Helm Commands

### Repository add

```bash
helm repo add <repo-name> <repo-url>
```

Example:

```bash
helm repo add bitnami https://charts.bitnami.com/bitnami
```

### Repositories dekhna

```bash
helm repo list
```

### Repository update

```bash
helm repo update
```

### Chart search

```bash
helm search repo nginx
```

### Install

```bash
helm install my-app ./my-chart
```

### Installed releases

```bash
helm list
```

### Upgrade

```bash
helm upgrade my-app ./my-chart
```

### Rollback

```bash
helm rollback my-app 1
```

### Uninstall

```bash
helm uninstall my-app
```
