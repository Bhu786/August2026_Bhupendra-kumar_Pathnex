## AWS Session Manager क्या है?

**AWS Systems Manager Session Manager** एक AWS Service है जिसकी मदद से आप **EC2 Instance में Secure तरीके से Login** कर सकते हैं, **बिना SSH Key, बिना Bastion Host और बिना Public IP** के।

### आसान भाषा में

पहले EC2 में Login करने के लिए आपको चाहिए होता था:

* Public IP
* SSH (Port 22)
* PEM Key
* Security Group में Port 22 Open

लेकिन Session Manager में इनकी जरूरत नहीं होती।

---

# इसकी जरूरत क्यों पड़ी?

मान लो Production Server है।

अगर SSH (Port 22) खुला रहेगा तो Hacker उस पर Attack कर सकते हैं।

इसलिए AWS ने Session Manager बनाया, जिससे SSH Port खोले बिना भी EC2 Access किया जा सके।

---

# यह क्या काम करता है?

### 1. Secure Login

SSH Key के बिना EC2 में Login कर सकते हैं।

```
Laptop
   │
AWS Console / AWS CLI
   │
Session Manager
   │
SSM Agent
   │
EC2 Instance
```

---

### 2. No Public IP Required

EC2 Private Subnet में हो तब भी Connect कर सकते हैं।

---

### 3. No Port 22

Security Group में SSH (22) खोलने की जरूरत नहीं।

---

### 4. Session Logging

आप कौन-सा Command चला रहे हैं, उसका Log CloudWatch या S3 में Store किया जा सकता है।

---

### 5. IAM Control

IAM से तय कर सकते हैं कि कौन User किस EC2 में Login कर सकता है।

---

### 6. Port Forwarding

Local Machine से Database (MySQL, PostgreSQL) तक Secure Connection बना सकते हैं।

---

### 7. File Transfer

Session Manager की मदद से Secure तरीके से Files Transfer भी कर सकते हैं।

---

✅ Production EC2

✅ Private Subnet EC2

✅ High Security Environment

✅ Banking Project

✅ Healthcare Project

✅ Enterprise Companies

# Session Manager के लिए क्या चाहिए?

1. EC2 पर **SSM Agent** Installed हो (Amazon Linux 2 में अक्सर पहले से होता है)
2. EC2 के साथ **IAM Role** Attach हो जिसमें `AmazonSSMManagedInstanceCore` Policy हो
3. Internet या VPC Endpoint के जरिए EC2, Systems Manager Service तक पहुँच सके

| ---------------------------- | ----------------------- |

| कम सुरक्षित                  | ज्यादा सुरक्षित         |

## AWS Route 53 क्या है?

**AWS Route 53** AWS की **DNS (Domain Name System)** Service है।

इसका काम **Domain Name (जैसे amazon.com)** को **IP Address** में बदलना और User की Request को सही Server तक पहुँचाना है।

---

# आसान भाषा में समझो

जब आप Browser में लिखते हो:

```text
www.amazon.com
```

Computer यह नहीं समझता।

उसे चाहिए IP Address जैसे:

```text
54.239.28.85
```

यह काम **Route 53** करता है।

```text
User
   │
www.amazon.com
   │
Route 53 (DNS)
   │
54.239.28.85
   │
EC2 / ALB / S3 / CloudFront
```

---

# इसकी जरूरत क्यों पड़ती है?

अगर Route 53 न हो तो हर Website का IP Address याद रखना पड़ेगा।

जैसे

❌ 54.239.28.85

❌ 142.250.193.78

इनकी जगह हम आसानी से लिखते हैं:

✅ google.com

✅ amazon.com

यही Route 53 की मदद से संभव होता है।

# Monitoring & Logging in AWS

# 1. AWS CloudTrail

## CloudTrail क्या है?

CloudTrail एक **Audit Logging Service** है जो AWS Account में होने वाली **सभी API Calls और User Activities** को Record करती है।

### आसान भाषा में

अगर कोई AWS Console या AWS CLI से कोई Action करता है, तो CloudTrail उसका पूरा Record रखता है।

उदाहरण:

* EC2 Launch
* EC2 Delete
* S3 Bucket Create
* IAM User Create
* Security Group Change
* RDS Delete

सब CloudTrail में Log हो जाता है।

---

## CloudTrail क्यों Use करते हैं?

* Security Audit
* Compliance (ISO, PCI DSS, HIPAA)
* Troubleshooting
* पता लगाने के लिए कि किसने क्या किया

---

## CloudTrail कैसे काम करता है?

```text
Admin / Developer
        │
AWS Console / CLI / SDK
        │
     API Call
        │
   AWS CloudTrail
        │
 Log File (JSON)
        │
S3 Bucket / CloudWatch Logs
```

---

## CloudTrail क्या-क्या Capture करता है?

* User Name
* API Name
* Service Name
* Time
* Source IP
* Region
* Success / Failure
* Resource Name

---

## Example

मान लो किसी ने EC2 Delete किया।

CloudTrail में Log आएगा:

```text

IP : 192.168.xx.xx

Region : ap-south-1
```

---

## CloudTrail के Use Cases

* किसने EC2 Delete किया?
* किसने IAM User बनाया?
* किसने S3 Bucket Delete किया?
* Unauthorized Activity Detect करना

# Interview Answer (1 Minute)

> **AWS CloudTrail is an audit service that records all API calls and user activities performed in an AWS account. It helps with security auditing, compliance, and troubleshooting by answering questions like who performed an action, when, and from where.**
>
> **AWS CloudWatch is a monitoring service that collects metrics, logs, and events from AWS resources such as EC2, RDS, Lambda, and ELB. It provides dashboards, alarms, and notifications (using Amazon SNS) to help monitor application performance and infrastructure health.**

# Serverless Computing (AWS Lambda)

## Serverless Computing क्या है?

**Serverless Computing** एक Cloud Computing Model है जिसमें आपको **Server Create, Manage, Patch या Scale** करने की जरूरत नहीं होती।

आप सिर्फ अपना **Code Upload** करते हैं, बाकी सब AWS Handle करता है।

* ✅ Server Provisioning
* ✅ Scaling
* ✅ OS Patching
* ✅ High Availability
* ✅ Maintenance

सब AWS करता है।

> **Serverless का मतलब "Server नहीं है" नहीं होता, बल्कि Server को Manage AWS करता है।**

---

# AWS Lambda क्या है?

**AWS Lambda** एक **Serverless Compute Service** है जो **Events आने पर आपका Code Automatically Run करती है।**

मतलब,

आप Function लिखते हैं और AWS उसे तभी चलाता है जब कोई Event Trigger होता है।

---

# इसकी जरूरत क्यों पड़ी?

पहले अगर छोटी-सी Script चलानी होती थी तो भी:

* EC2 Launch करो
* OS Install करो
* Patch करो
* Server Monitor करो
* Auto Scaling Configure करो

बहुत Overhead था।

Lambda में:

* Code Upload करो
* Trigger सेट करो
* बस!

# Lambda की मुख्य विशेषताएँ

### 1. No Server Management

EC2 Manage करने की जरूरत नहीं।

---

### 2. Event Driven

Event आते ही Function Run होता है।

---

### 3. Auto Scaling

1 Request आए या 10,000 Request,

Lambda Automatically Scale हो जाती है।

---

### 4. Pay Per Use

जितनी देर Function चला, उतना ही पैसा।

Idle रहने का कोई Charge नहीं।

---

### 5. Stateless

हर Invocation Independent होती है।

# Event-Driven Automation क्या है?

**Event-Driven** का मतलब है:

> **जब कोई Event हो, तब Automatically कोई Action Perform हो।**

कोई Manual Intervention नहीं।

# Lambda vs EC2

| ----------------- | ------------------------------ | ------------------------------------ |
| Server Management | AWS करता है                    | User करता है                         |

# Interview Answer (1 Minute)

> **AWS Lambda is a serverless compute service that allows you to run code without provisioning or managing servers. It executes code in response to events such as S3 uploads, API Gateway requests, EventBridge schedules, or DynamoDB changes. Lambda automatically scales based on incoming requests and follows a pay-per-use pricing model. It is commonly used for event-driven automation, backend APIs, file processing, scheduled tasks, and serverless applications.**
