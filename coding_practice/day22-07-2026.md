**Ansible is an open-source automation tool used for configuration management, application deployment, and task automation.**
It helps us **automate repetitive tasks** like:
* Installing software
* Configuring servers
* Deploying applications
* Managing multiple servers

### Why Ansible?
1. **Automation** – Reduces manual work.
2. **Consistency** – Configures all servers in the same way.
3. **Scalable** – Can manage hundreds or thousands of servers.
4. **Agentless** – No Ansible agent is required on remote servers.
5. **Easy to use** – Uses simple **YAML** files

### How does Ansible communicate?
* **Linux/Unix → SSH**
* **Windows → WinRM**

## How Ansible Works
**Control Node → Inventory → Connect to Servers → Execute Modules → Get Result**

## Main Components
### 1. Control Node
The machine where Ansible is installed and commands are executed.
### 2. Managed Nodes
The remote servers that Ansible manages.
### 3. Inventory
Contains the list of servers.
Example:
```ini
[webservers]
server1
server2```
## 4. Playbook
A **YAML file** containing the tasks Ansible should perform.
### 5. Module
Modules perform actual operations such as:
* Install package
* Copy files
* Start services
* Create users
### 6. Role
Roles organize Ansible code into **reusable structures**.

## Common Use Cases
* Server configuration
* Application deployment
* Software installation
* Patch management
* User and permission management
* Cloud resource management
* CI/CD automation


## How Ansible Works
**Control Node → Inventory → Connect to Servers → Execute Modules → Get Result**
For example:
> I create an Ansible playbook to install Nginx on 10 servers. Ansible connects to all servers through SSH, installs Nginx, starts the service, and reports the result.


## Basic Command

```bash
ansible-playbook -i inventory webserver.yml
```
