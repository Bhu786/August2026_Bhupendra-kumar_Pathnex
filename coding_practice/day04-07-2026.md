# User Management in Linux

## 1. Create a New User

**Command:**

```bash
sudo useradd bhupendra
```

Ya home directory ke saath:

```bash
sudo useradd -m bhupendra
```

Password set karein:

```bash
sudo passwd bhupendra
```

Example:

```bash
sudo useradd -m john
sudo passwd john
```

---

## 2. Check User Information

Current user:

```bash
whoami
```

Current user's UID:

```bash
id
```

Specific user details:

```bash
id john
```

---

## 3. List All Users

```bash
cat /etc/passwd
```

Sirf usernames:

```bash
cut -d: -f1 /etc/passwd
```

---

## 4. Create a Group

```bash
sudo groupadd developers
```

Verify:

```bash
cat /etc/group
```

---

## 5. Add User to a Group

```bash
sudo usermod -aG developers john
```

Multiple groups:

```bash
sudo usermod -aG developers,docker john
```

Check groups:

```bash
groups john
```

---

## 6. Remove User from a Group

```bash
sudo gpasswd -d john developers
```

---

## 7. Change Primary Group

```bash
sudo usermod -g developers john
```

---

## 8. Delete a User

User only:

```bash
sudo userdel john
```

User with home directory:

```bash
sudo userdel -r john
```

---

## 9. Delete a Group

```bash
sudo groupdel developers
```

---

# Permissions

## View Permissions

```bash
ls -l
```

Example:

```text
-rwxr-xr--
```

Meaning:

| Symbol | Permission |
| ------ | ---------- |
| r      | Read       |
| w      | Write      |
| x      | Execute    |

---

## Change Permissions

Numeric Method

```bash
chmod 755 file.txt
```

Explanation:

```
7 = rwx
5 = r-x
5 = r-x
```

Other examples:

```bash
chmod 777 file
chmod 644 file
chmod 600 file
```

---

Symbolic Method

```bash
chmod u+x script.sh
chmod g+w file.txt
chmod o-r file.txt
```

---

## Change Owner

```bash
sudo chown john file.txt
```

Owner and group together:

```bash
sudo chown john:developers file.txt
```

---

## Change Group Only

```bash
sudo chgrp developers file.txt
```

# Interview Questions

### Q1. Difference between `useradd` and `adduser`?

* **useradd**: Low-level command, manual setup.
* **adduser**: User-friendly script, automatically creates home directory and prompts for user details (mainly Debian/Ubuntu).

---

### Q2. Difference between Primary Group and Secondary Group?

* **Primary Group**: Default group assigned to the user.
* **Secondary Group**: Additional groups that provide extra permissions.

---

### Q3. What does `chmod 755` mean?

* Owner: `rwx`
* Group: `r-x`
* Others: `r-x`

---

### Q4. Difference between `chown` and `chmod`?

* **chown** changes the owner/group of a file.
* **chmod** changes the file's permissions.

---

### Q5. How do you check which groups a user belongs to?

```bash
groups username
```

or

```bash
id username
```

### Sudo Privileges (Short Notes)

* **Sudo** allows a normal user to run commands with **admin (root) privileges**.
* **Ubuntu/Debian:**

  ```bash
  sudo usermod -aG sudo username
  ```
* **RHEL/CentOS:**

  ```bash
  sudo usermod -aG wheel username
  ```
* **Verify groups:**

  ```bash
  groups username
  ```
* **Logout & Login again** to apply the new group membership.
* **Test sudo:**

  ```bash
  sudo whoami
  ```

  Output:

  ```text
  root
  ```
* **Sudo configuration file:**

  ```text
  /etc/sudoers
  ```

  Edit safely using:

  ```bash
  sudo visudo
  ```

### Interview Answer (30 sec)

> "Sudo gives a normal user temporary root privileges. We grant sudo access by adding the user to the `sudo` (Ubuntu) or `wheel` (RHEL) group. After that, the user should log out and log back in for the changes to take effect. We can verify it using `sudo whoami`, which should return `root`."

## Security Practices – Jump Server (Bastion Host) (Short Notes)

* **Jump Server (Bastion Host)** is a **secure intermediate server** used to access private servers.
* Instead of allowing SSH access to every server from the internet, users **first connect to the Bastion Host**, then access private servers.
* This improves **security** by reducing direct exposure of internal servers.

### Flow

```text
User
  │
SSH
  │
Bastion Host (Public Subnet)
  │
SSH
  │
Private EC2 / Application Server (Private Subnet)
```

### AWS Example

* **Bastion Host** → Public Subnet (has Public IP)
* **Application/DB Servers** → Private Subnet (No Public IP)
* SSH is allowed **only from the Bastion Host** to private servers.

### Benefits

* ✅ No direct internet access to private servers
* ✅ Better security
* ✅ Centralized access management
* ✅ Easy monitoring and logging
* ✅ Reduces attack surface

### Interview Answer (30 sec)

> "A Bastion Host, also called a Jump Server, is a secure server placed in a public subnet. Administrators first SSH into the Bastion Host and then connect to servers in the private subnet. This prevents direct internet access to private servers and improves the overall security of the infrastructure."

## File Operations (Short Notes)

### 1. Change File Owner – `chown`

Changes the **owner** of a file or directory.

```bash
sudo chown username file.txt
```

Change owner and group together:

```bash
sudo chown username:groupname file.txt
```

**Example:**

```bash
sudo chown bhupendra:developers app.log
```

---

### 2. Change Group – `chgrp`

Changes the **group ownership** of a file.

```bash
sudo chgrp developers file.txt
```

---

### 3. Archive & Compress – `tar`

Create a tar archive:

```bash
tar -cvf archive.tar folder/
```

Create a compressed tar.gz archive:

```bash
tar -czvf archive.tar.gz folder/
```

Extract a tar file:

```bash
tar -xvf archive.tar
```

Extract a tar.gz file:

```bash
tar -xzvf archive.tar.gz
```

---

## Common `tar` Options

* `-c` → Create archive
* `-x` → Extract archive
* `-v` → Verbose (show progress)
* `-f` → Specify file name
* `-z` → Gzip compression

---

## Interview Answer (30 sec)

> "`chown` is used to change the owner of a file or directory, `chgrp` changes the group ownership, and `tar` is used to archive and compress files. Common commands are `tar -czvf` to create a compressed archive and `tar -xzvf` to extract it."
