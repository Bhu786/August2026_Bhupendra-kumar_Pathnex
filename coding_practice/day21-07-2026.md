Terraform State Locking*
**1. The Problem: Concurrent State Conflicts (0:00 - 0:45)**

> "When multiple DevOps engineers or automated CI/CD pipelines run `terraform apply` at the exact same time, they compete to read and write to the same `terraform.tfstate` file. Without protection, this race condition leads to state corruption, overwriting configurations, or provisioning duplicate infrastructure in production."
---
**2. The Solution: How State Locking Works (0:45 - 1:45)**

> "Terraform solves this using **State Locking**. Before executing operations like `plan`, `apply`, or `destroy`, Terraform sends a lock request to the remote backend. If granted, Terraform locks the state, performs the operation, and unlocks it upon completion. If someone else attempts a run simultaneously, Terraform blocks execution and displays a `Lock ID` along with who currently holds the lock."

**4. Real-World Handling: Stuck Locks (2:30 - 3:30)**

* **What to say**:
> "In production, if a CI/CD job crashes midway or loses connectivity, a lock might stay stuck in an active state. To resolve this, you verify no active deployment is running, then manually run:
> `terraform force-unlock <LOCK-ID>`
> This safely clears the stale lock so the team can resume deployments."
